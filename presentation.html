01 • Problem Statement

Use Case & Pain Points ในโรงงานอุตสาหกรรม

Unplanned Downtime Crisis
⚠️

1. ความเสียหายจากการหยุดเครื่องกะทันหัน

ตลับลูกปืน (Bearings) ชำรุดเฉียบพลัน ทำให้สายการผลิตหยุดชะงัก (Unplanned Downtime) ก่อให้เกิดความเสียหายเฉลี่ยสูงถึง หลักแสนถึงหลักล้านบาทต่อชั่วโมง ในโรงงานผลิต

ปัญหา: ขาดการแจ้งเตือนล่วงหน้าที่แม่นยำ
⏳

2. การซ่อมบำรุงตามรอบเวลาไร้ประสิทธิภาพ

วิธี Preventive Maintenance (PM) ดั้งเดิมซ่อมตามชั่วโมงทำงาน ทำให้เกิด Over-maintenance (ทิ้งอะไหล่ที่ยังดี) หรือ Under-maintenance (อะไหล่เสียหายก่อนถึงรอบตรวจ)

ปัญหา: สิ้นเปลืองงบประมาณอะไหล่และค่าแรง
🧠

3. ขาดแคลนผู้เชี่ยวชาญ & AI Hallucination

การอ่านกราฟ FFT ต้องใช้ผู้เชี่ยวชาญเฉพาะทาง ขณะที่โมเดล GenAI/LLM ทั่วไปไม่สามารถคำนวณอายุคงเหลือ (RUL) ได้ถูกต้อง มักเกิดอาการ "AI หลอน" (Hallucination) ซึ่งอันตรายต่อความปลอดภัย

ปัญหา: Black-box AI ไม่น่าเชื่อถือในงานวิศวกรรม
🎯 โจทย์ท้าทาย: ทำอย่างไรให้ตรวจจับได้แบบเรียลไทม์ 24/7 ตัวเลข RUL เชื่อถือได้ 100% และระบบมีต้นทุนต่ำที่สุด? Answer: MechAgent Physics-Informed Serverless
02 • The Innovation

AWS Solution & จุดเด่นของ MechAgent

Zero Hallucination Architecture
🔬

1. Physics-Informed Multi-Task Learning (MTL) AI

ผสานโครงข่ายประสาทเทียม 1D-CNN Backbone ร่วมกับสูตรฟิสิกส์ Envelope Spectrum คำนวณ Order Frequencies (BPFI, BPFO, BSF, FTF) พร้อมกัน 3 มิติ: ตำแหน่งชำรุด, ระดับความเสื่อม (ISO S0-S4), และอายุคงเหลือ (RUL) โดยไม่ผ่าน LLM ทำให้ Zero Hallucination 100%

🛡️

2. Worst-Case P05 Safety Deadline (Monte Carlo)

ใช้ Monte Carlo Dropout ประเมิน Epistemic Uncertainty ของตลับลูกปืน และนำค่าความเสี่ยงเลวร้ายที่สุด (P05 Worst-case) มากำหนดเป็นเส้นตายเปลี่ยนอะไหล่ ป้องกันเครื่องจักรล็อกเฉียบพลันในระดับความปลอดภัยสูงสุด

🤖

3. Autonomous Agentic Workflow & Human-in-the-Loop

มี Gatekeeper Filter คัดกรองเคสฉุกเฉินส่งให้ Amazon Bedrock (Nova Pro) สรุปงานซ่อม ตรวจสอบสต็อกอะไหล่ จัดทำใบสั่งงาน (Work Order) และมีระบบอนุมัติสำหรับหัวหน้างาน (Approve / Postpone / Reject) พร้อมออก Cryptographic Verification Token

📂

4. รองรับทั้ง Simulation และ Real Lab Dataset

สามารถจำลองสัญญาณตามทฤษฎีกลศาสตร์ และรองรับการนำเข้าข้อมูลจริงจากห้องแล็บระดับโลก (CWRU .mat และ XJTU-SY .csv) พร้อมตัวตรวจจับความเร็วรอบ RPM และคำนวณ RMS อัตโนมัติ

BPFI: Inner Race Order
BPFO: Outer Race Order
BSF: Ball Spin Order
FTF: Cage Defect Order

05 • Architecture Evolution

Before vs. After: ก้าวกระโดดสู่ Serverless

Transformation Matrix
มิติการเปรียบเทียบ 🔴 สถาปัตยกรรมเดิม (Traditional EC2 Server) 🟢 สถาปัตยกรรมใหม่ (100% Serverless First)
1. ค่าใช้จ่ายขณะไม่มีโหลด (Idle Cost) 💸 เสียเงินตลอด 24 ชม. แม้โรงงานจะหยุดทำงาน (EC2 t3.small ~$22/เดือน + EBS) 🟢 $0.00 (Zero Idle Cost) ไม่มีการสั่นสะเทือนส่งเข้ามา = ไม่เสียเงินแม้แต่บาทเดียว
2. การรองรับผู้ใช้งาน (Scalability) ⚠️ ติดคอขวดที่ขนาด RAM/CPU ของเครื่องเดี่ยว เกิดปัญหา Crash เมื่อมีโหลดเข้าพร้อมกัน 🟢 Auto-scaling อัตโนมัติในเสี้ยววินาที รองรับเครื่องจักรพร้อมกันหลักหมื่นเครื่อง
3. ความพร้อมใช้งาน (High Availability) ⚠️ Single Point of Failure (SPOF) หาก OS แฮงก์ หรือ VM ดับ ระบบจะล่มทันที 🟢 Multi-AZ Fault Tolerant สถาปัตยกรรมกระจายตัวบนหลายศูนย์ข้อมูล อัตโนมัติ 99.99%
4. ความปลอดภัย & โดเมน (Security & SSL) ⚠️ เรียกผ่านหมายเลข IP ตรงๆ พร้อมพอร์ตแปลกปลอม :8501 ขึ้นเตือน `Not secure` 🟢 HTTPS แม่กุญแจเขียว 🔒 ผ่าน CloudFront CDN มาตรฐาน Enterprise ปิดพอร์ตเสี่ยง
5. ภาระการดูแลระบบ (Maintenance Overhead) ⚠️ ต้องคอยอัปเดต Linux Kernel, Patch OS, ซ่อมแซม Driver และแพ็กเกจ 🟢 NoOps ไร้ภาระดูแลเซิร์ฟเวอร์ วิศวกรทุ่มเทเวลาให้กับการพัฒนาโมเดล AI ได้ 100%
Cost Reduction: > 90% Deployment Flexibility: CloudFormation & SAM Declarative Code
